# PCモード（物理キーボード）

物理キーボードで打つときに、ソフトキーボードの代わりに **言語バー** と **カーソルの下の候補ウィンドウ** を出すモードです。操作は Windows の IME（Microsoft IME の既定、US 配列）に合わせています。

変換の処理（`InputHandler`）はソフトキーボードと共通です。このフォルダには、物理キーを `InputHandler` の呼び出しに翻訳する層と、PC 向けの画面だけがあります。

## ファイル

| ファイル | 役割 |
|---|---|
| `PcModeController.ets` | まとめ役。PCモードの入り切り、パネルの切り替え、言語バーと候補ウィンドウの置き場所 |
| `PhysicalKeyRouter.ets` | `KeyboardDelegate.on('keyEvent')` の処理。キーを消費するか素通しするかを決め、`InputHandler` を呼ぶ |
| `KeyMap.ets` | US 配列のキー表、文字の幅の書き換え（全角・半角・半角カタカナ）、かな→ローマ字 |
| `KeyboardDeviceMonitor.ets` | 物理キーボードの接続を `inputDevice` で見張る |
| `PcSettings.ets` | 設定（PCモード: 自動 / オン / オフ、言語バーの位置） |
| `CandidateViewModel.ets` | 候補ウィンドウに何を出すか、窓の大きさ（コントローラと画面の両方が使う） |
| `PcCandidateWindow.ets` | 候補ウィンドウの画面（Windows 11 風） |
| `PcPopupView.ets` | 言語バーから開く絵文字・設定（既存の EmojiView / SymbolView / SettingsBar をそのまま表示） |
| `PcStyle.ets` | 色と寸法 |
| `../pages/LangBarPage.ets` | 言語バーの画面 |

## パネルの使い方

入力メソッドが作れるパネルは **SOFT_KEYBOARD 1 枚と STATUS_BAR 1 枚まで** です（`createPanel` の説明）。

- **STATUS_BAR**: 言語バー。入力欄にいる間だけ表示する。`moveTo` は FLG_FIXED のパネルには効かないので、FLG_FLOATING で作る。
- **SOFT_KEYBOARD**: 1 枚を使い回す。中身は `AppStorage('pcSoftContent')` を見て `KeyboardPage` が描き分ける。

| pcSoftContent | flag | 中身 | 置き場所 |
|---|---|---|---|
| `candidate` | `FLAG_CANDIDATE`（API 15） | 候補ウィンドウ | カーソルの下（入らなければ上） |
| `popup` | `FLAG_CANDIDATE` | 絵文字・設定 | 言語バーの上（言語バーが上半分にあれば下） |

設定の「レイアウト調整」と辞書の登録は実物のキーボードの画面を使うので、始めたら仮想キーに切り替えます。
| `keyboard` | 固定 / フローティング（設定どおり） | 今までのソフトキーボード（仮想キー） | 今までどおり |

`FLAG_CANDIDATE` のパネルはサービスが勝手に表示・非表示にしないので、入力中だけ自分で出します。PCモードでソフトキーボードのパネルを FIXED のままにしておくと、アプリがキーボードを要求したときにサービスがソフトキーボードを出してしまうため、PCモード中は何も出していないときも `FLAG_CANDIDATE` にしておきます。

flag の切り替えは `setFloatingMode` と同じ手順です（隠す → `changeFlag` → 100ms 待つ → 置き直す → 出す）。

## キーの扱い

### 共通
- **英字モード（A）**: IME の切り替えキー以外はすべてアプリへ素通し（直接入力）。
- **IME のオン・オフ**: 半角/全角キー、`Alt+``、言語バーのモードボタン。カタカナひらがなキーはオン、英字モードで変換キーもオン。
- **Ctrl / Alt / Win との同時押し**: 入力中なら確定してから素通し。
- 何も入力していないときの Enter・BackSpace・Delete・矢印・Tab・Esc・F キーは素通し。
- keyDown を消費したキーは keyUp も消費する。

### 何も入力していないとき（ひらがなモード）
- 文字キー: 読みを打ち始める。記号は全角の和文の字（`,`→`、` `.`→`。` `[`→`「` `/`→`・`）。数字は半角のまま（ソフトキーボードと同じ。変換は半角の数字の読みを前提にしている。全角にしたいときは F9）。
- Space: 全角空白、Shift+Space: 半角空白。

### 読みを打っているとき
| キー | 動作 |
|---|---|
| Space / 変換 / ↓ / Tab | 変換（裏の AI 変換を待たずにその場で変換し、打っている間は後回しにしている候補も足す） |
| Enter | かなのまま確定 |
| BackSpace | 1 字消す |
| Esc | 読みを捨てる |
| ← → | 変換する範囲を縮める・伸ばす（ソフトキーボードの ◄ ► と同じ） |
| F6〜F10 | ひらがな / 全角カタカナ / 半角カタカナ / 全角英数 / 半角英数（F9・F10 は押すたびに 小文字→大文字→先頭だけ大文字） |
| 無変換 | 全角カタカナ |
| Delete・Home・End・Insert・↑・PageUp/Down | 飲み込む（確定前の文字の外でカーソルが動かないように） |
| その他（F1〜F5 など） | 確定してから素通し |

### 変換中
| キー | 動作 |
|---|---|
| Space / ↓ / 変換 / Tab | 次の候補 |
| Shift+Space / ↑ / Shift+Tab | 前の候補 |
| PageUp / PageDown | ページ送り（9 件ずつ） |
| 1〜9 | 今のページのその番号で確定 |
| Enter | 確定 |
| Esc / BackSpace | 読みに戻る（打っている間の候補を出し直す） |
| ← → | 文節ごとに選び直すモードへ |
| Shift+← → | 変換する範囲を縮める・伸ばす |
| 文字キー | 選んでいる候補で確定して、次の読みを打ち始める |

### 文節ごとに選び直しているとき
← → で文節を移り、Space・↑↓ で今の文節の候補を選ぶ（選んだ候補はすぐその文節の表記になる）。1〜9 はその文節を決めて次の文節へ。Enter で全部確定、Esc・BackSpace で読みに戻る。

末尾に残った `n` は、変換・確定するときに「ん」にする（`hon` + Space で「本」）。ソフトキーボードは今までどおり。

変換中に一覧が出し直されたとき（裏の変換が後から届いた・範囲を変えた）は、選んでいた候補を選んだままにする。

## 言語バーの表示

表示中かどうかを、こちらの印と、パネルの `show` / `hide` の知らせの両方で追う。

- 入力欄に入るたびに `show()` を呼ぶ（もう出ていれば何も起きない）。300ms 後に実際に出ていなければもう一度出す。
- 出しているつもりなのに OS に隠されたら、150ms 後に出し直す（入力欄ごとに 3 回まで）。
- 作っている途中に来た「出して」は、作り終わってから今の状態を見て出す。
- 作るのに失敗したら、次に入力欄に入ったときに作り直す（3 回まで。キーボードをつなぎ直すと数え直す）。

## 入力欄の表示
入力欄が下線付きの表示（`setPreviewTextSync`）に対応していれば、変換中は選んでいる候補を、文節の編集中は文節の表記をつないだものを入力欄に出します（ソフトキーボードは今までどおり読みを出す）。対応していない欄では、候補ウィンドウの一番上に読みを出します。

## 実機で確かめること（SDK の説明からは分からない点）

1. `keyEvent` の `ctrlKey`・`altKey`・`unicodeChar` が入力メソッド側でも正しく入るか（修飾キーは `keys` からも判定している）。
2. 半角/全角・変換・無変換・`Alt+`` がシステムに取られずに届くか。
3. `cursorContextChange` の座標が画面の px か（ウィンドウの中の座標なら候補ウィンドウがずれる）。座標が来ない欄では言語バーの上に出す。
4. STATUS_BAR パネルを FLG_FLOATING で作れるか・`moveTo` で動かせるか。作れない端末では言語バー無しで続ける（キーでモードは切り替えられる）。
5. `FLAG_CANDIDATE` のパネルを隠したときに `inputStop` が来ないか（来ると入力欄から外れた扱いになる）。
6. パネルの窓の背景が透明か（候補ウィンドウ・言語バーの影は窓の余白に描いている）。
7. 言語バーのドラッグ（PanGesture のずれで `moveTo`）がマウスで追従するか。追従が悪ければ `Panel.startMoving()`（API 15）に切り替える。
8. 物理キーボードの判定（`inputDevice` の ALPHABETIC_KEYBOARD・仮想でない）。外れる端末向けに、文字キーが届いたら機器を調べ直す・設定で「オン」にする逃げ道がある。

## まだ無いもの
- 読みの途中へのカーソル移動（← → は変換範囲の調整に使っている）
- 文節の区切りを Shift+← → で動かす
- 候補の Tab での表形式の展開
- 再変換
- かな入力（物理キーボードのかな配列）・JIS 配列
